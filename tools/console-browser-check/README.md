# 控制台真浏览器检查

在真浏览器里把控制台的离线演示各页打开一遍，抓下面三类毛病，并给每一轮截一张整页图。
控制台已有的 node 检查只跑视图模型（DOM 用自写的小桩），这三类毛病它们抓不到：

1. 页面脚本一加载就报错，结果白屏或半截页面；
2. 页面引用的样式、脚本、图标找不到（地址写错、占位没换），结果没样式或白屏；
3. 手机宽度下页面横向溢出，要左右拖着看。

## 测不到什么

- 成员身份看到的页面：演示没有成员身份的录包，只看管理员视角；
- 保存后的真实效果：演示里的保存只模拟回包，不落盘、不生效；
- 直播中的状态：录包里没有正在直播的主播；
- 扫码登录与通行密钥：需要真实设备或服务；
- 页面交互：只打开页面、等它稳定，不点按钮、不填表。

## 准备浏览器

用 Chrome for Testing 的 chrome-headless-shell：在
<https://googlechromelabs.github.io/chrome-for-testing/> 选与本机平台对应的
`chrome-headless-shell` 压缩包，解压后可执行文件就是其中的 `chrome-headless-shell`。
另需 node 22 或更高版本，以及导出演示要用的 bash 和 python3。不装 npm 包。

## 跑法

```sh
NOVA_CHROME=/path/to/chrome-headless-shell sh tools/console-browser-check/run.sh
# 或
sh tools/console-browser-check/run.sh --chrome /path/to/chrome-headless-shell
```

可用 `--out 目录` 换结果目录，默认 `target/console-browser-check/`。结果目录在仓库里时必须被
git 忽略，跑完还会再核一次，跑出来的东西不会进提交。

脚本先把离线演示（`tools/demo-assets/export-console-demo.sh`）导出到临时目录，再用 node
跑 `check.mjs`。共 9 个界面 × 2 种宽度 × 2 种颜色，36 轮：

- 界面：`/config/` 下的 `#/home` `#/push` `#/streamers` `#/log` `#/links` `#/settings` `#/setup`，
  以及 `/config/login/`、`/config/napcat-bootstrap/`；
- 宽度：桌面 1440×900；手机 390×844，按手机方式仿真；
- 颜色：浅色、深色。页面脚本运行前写好 localStorage 的 `novabot-theme`，同时把
  prefers-color-scheme 仿真成同色。

每轮开一个新标签页，并在打开页面前清空该来源的存储，轮与轮互不影响。

### 不占端口，不出网

浏览器以 `--remote-debugging-pipe` 启动，调试协议走两条命名管道（FIFO），不监听端口，
也不建套接字。页面开在 `http://localhost:8000/config/...`，那里并没有服务：浏览器发出的每个
请求都由调试协议的请求拦截接住，从导出目录读文件回给它，按扩展名给 Content-Type。
发往 localhost:8000 以外的请求一律拦下，只在结果里列出。

macOS 上浏览器以 `--single-process` 启动（默认的多进程起法在沙箱里会被拒），Linux 上不加。
单进程时在新建的浏览器上下文里开标签页会让浏览器崩溃，所以各轮都开在默认上下文里，靠清空存储隔离。

## 怎么判

载完以后网络空闲 0.5 秒算稳定，最多等 15 秒。

| 情形 | 判 |
|---|---|
| 页面脚本抛出没接住的异常，或有没处理的 Promise 拒绝 | 失败 |
| 本地资源（`/config/api/` 以外）在导出目录里找不到 | 失败 |
| 稳定后页面主体没有可见文字（白屏；演示自带的提示条不算） | 失败 |
| 手机宽下页面比视口宽 | 失败，并列出最多 3 个伸出视口最多的元素 |
| 15 秒还没稳定 | 失败 |
| 演示没录的接口，或页面上出现「离线演示未录制」一类提示 | 只列出 |
| console.error | 只列出 |
| 发往 localhost:8000 以外的请求（比如主播头像） | 拦下、只列出 |

演示的录包停在录制那天，之后新加的接口没有录，所以「没录的接口」在意料之中，不判失败。

## 输出

结果目录里：

- `summary.txt`，同时打到标准输出：每轮一行 `页 宽 色 通过|失败 原因`；然后一行
  `合计 36 轮：通过 X，失败 Y`；再按页列出只列出、不判失败的几类，括号里是出现的轮数；
- `<页>-<宽>-<色>.png`：每轮一张整页截图，例如 `home-390-dark.png`；
- `browser.log`：浏览器自己的输出；`export.log`：导出演示的输出。

有的环境里截图命令一直没有回应，浏览器也随之不再应答（例如不许访问窗口服务的 macOS 沙箱，
页面尺寸一大就会这样）。遇到这种情况，脚本换一个新浏览器接着查，之后的各轮照常检查但不再截图，
`summary.txt` 第二行写明从哪一轮起没有截图。

## 退码

- `0`：36 轮全部通过；
- `1`：有失败的轮；
- `2`：跑不起来，并打一句说明缺什么（没有 node 22 以上、没给浏览器、导出失败、浏览器起不来等）。
