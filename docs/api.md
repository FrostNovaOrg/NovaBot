# 程序接口约定（`/nova/api/v1/`）

给「别的程序来调 NovaBot」用的统一接口面：地址前缀、鉴权方式、返回格式、错误代码都在这一份里定死，
以后的对外接口一律挂在这个前缀下、照这份约定办。

底座自带自查接口 `GET /nova/api/v1/me`。插件提供的接口挂在 `/nova/api/v1/<插件的段名>/` 下。
装了「外发」插件的实例可以通过下文「外发箱」的接口取件。下文「推送」一组随核心提供，管理员的令牌可以凭它请 NovaBot 代发消息。
同一把访问令牌勾上「读取事件流」，还能在本机连事件输出 `/nova/events`，见下文「事件流」。

怎么在控制台签发、吊销访问令牌，另一台机器怎么连，见使用说明
[附录 B「让脚本或别的程序调用 NovaBot」](https://frostnovaorg.github.io/NovaBot/appendix-b-advanced.html)。

## 地址前缀

```
http://<NovaBot 所在机器>:<端口>[<部署前缀>]/nova/api/v1/
```

端口与控制台相同（默认 7827）。配了 `server.servlet.context-path` 时，前缀接在它后面。
版本号写在路径里：日后有不兼容的改动会另开 `v2`，`v1` 下已有的接口不改语义。

## 鉴权

只认一种写法：

```
Authorization: Bearer <访问令牌>
```

- 访问令牌在控制台「访问令牌」页签发，形如 `nvb_` 后接 43 个字符（32 字节随机数的 base64url）。
- **不认** 控制台的会话 Cookie，**不认** 地址栏里的 `?token=`、`access_token=` 之类参数，也不认别的请求头。
  地址栏里的东西会进反向代理日志与浏览器历史；Cookie 是浏览器自动附上的，认它就等于让任何网页都能借你的登录调接口。
- 反过来，访问令牌也**进不了控制台**：控制台只认登录会话和启动令牌。
- 令牌的权限始终跟着**所属账号此刻的状态**：管理员改了成员名下的主播，成员的令牌从下一个请求起按新名单算；
  成员被改成管理员，令牌也随之按管理员算；管理员被改成成员，令牌也随之按成员算（含下文「仅管理员」的范围）。

### 令牌什么时候失效

| 情形 | 结果 | 能不能恢复 |
|---|---|---|
| 过了有效期 | 401 | 不能，重新签发 |
| 在控制台吊销 | 401 | 不能，重新签发 |
| 所属账号被停用或删除 | 名下全部令牌**一并吊销**，401 | 不能：账号重新启用后，旧令牌仍是已吊销，要重新签发 |
| 所属账号是成员，而成员此刻登录不了控制台（例如单点登录关着） | 暂不可用，401 | 能：成员能登录了，下一个请求起照常可用，不用重签 |

成员只有单点登录一条路进控制台，所以「成员此刻登录不了」就是单点登录此刻没开（统一登录没配、或控制台的登录口令被撤掉）。
管理员的令牌不受这一条影响。控制台总开关关着时谁也登不进，这时按配置判：设了登录口令、开着统一登录，
成员的令牌照常可用——控制台关着时这个前缀照常服务，见下文「控制台关着时」。
控制台列表里这种令牌显示「暂不可用」并写明原因。

成员此刻登录不了时的回包，与账号被停用、删除时一字不差（401 `unauthenticated`，同一句说明）。

### 来源地址

每个请求先判出**来访者**，再按控制台设置页的「允许访问的来源 IP」名单（`novabot.core.config-ui.allow-ips`，默认只有本机两条）放行。
来访者这样判（只用于这个前缀；控制台、事件流、推送接口各有各的判法，不受影响）：

| 连进来的那一端 | 请求里的转发头 | 来访者 |
|---|---|---|
| 不是本机回环 | 一概不看 | 就是连进来的那一端 |
| 本机回环 | 没有 `X-Forwarded-For`、`X-Real-IP`、`Forwarded` | 本机 |
| 本机回环 | 带了其中一种或几种 | 经本机的反向代理进来，取离 NovaBot 最近的那一段（见下） |

取法：`X-Forwarded-For` 取**最右一段**（这个头是追加式的，最左边那几段由客户端说了算，最右一段是本机那层代理写上的）；
`X-Real-IP` 只认一行、一个值；`Forwarded` 取最后一项里的 `for=`。只认 IP 字面量（可带端口，IPv6 可带方括号）。
带了几种就几种都要解析得出、而且指的是同一个地址。

**转发头里只要有一处写得不合规，整个就当作未知来访者，不跳过那一处、退而采用别的一段。** 下面这些都算不合规：

- `X-Forwarded-For` 里有一段是空的（末尾多了逗号、中间两个逗号连着、整个头是空的），或任何一段（不只最右那一段）不是合法地址；
- `X-Real-IP` 写了不止一行，或值里有逗号，或不是合法地址；
- `Forwarded` 按它自己的写法读不干净：空项、参数名或值是空的、少了等号、引号没收口或后面跟着别的字、
  分号两侧或等号两侧有空白（逗号两侧的空白可以有）；引号里出现反斜杠、逗号、分号、等号、空白或控制字符；
  同一项里一个参数写了两次；某一项没有 `for=`；任何一项的 `for=` 不是合法地址（`unknown`、`_hidden` 也算）。
  不带引号的值里不能有冒号和方括号，所以带端口的、IPv6 的地址要带引号，例如 `for="[2001:db8::17]:4711"`；
- 地址不是 IP 字面量：主机名、`127.1` 这类简写、带区域标识（`%eth0`）的、方括号不配对的；
- 端口不在 1–65535，或带前导零（`:080`）；
- 几种头说的不是同一个地址。

未知来访者不是本机，也不在任何名单里。

名单之外的来访者回 403 `source_not_allowed`，**除非**请求的这组接口被设成了对任何地址开放（见下一节）。

前提是本机上的反向代理把转发头写好（使用说明附录 C 的样板已写好）。代理一个转发头也不写的话，
经它进来的请求与本机直连分不出来，都算本机来访——这种代理不要拿来转发这个前缀。
NovaBot 前面直接连着的不是本机代理（代理在另一台机器上）时，看到的来访者就是那台代理，名单要按它写。

不需要、也不建议为这个前缀打开 `server.forward-headers-strategy`：这个前缀自己认转发头，
而那一项会把控制台与事件流的来源判断一并改写。推送接口那边的「信任反向代理」（`trust-proxy`）只管推送接口，对这个前缀不起作用。

**名单是与控制台共用的**：把一台远程机器加进名单，让它能调这个前缀，它同时也就能打开控制台的登录页
（控制台照样要登录）。只想让它调某一组接口，用下一节的按组开放；什么设置都不想改，用 SSH 隧道
（见使用说明附录 B「从另一台机器连」）。

#### 按组对任何地址开放

设置项 `novabot.core.config-ui.api-any-source-groups` 是「对任何来源地址开放的接口组」清单，每行一个组名
（`/nova/api/v1/` 之后的第一段，例如 `outbox`），**默认为空**。保存即生效，不用重启。
建议在控制台「访问令牌」页的「从别的机器访问」里逐组打开（只有管理员看得到），打开时会先问一句。

- 来访者不在名单里、请求的这组在清单里：接着往下走，仍须有效令牌与范围（含仅管理员的范围），
  无效令牌照常计限速，路径写法照常检查。**开放只免去来源名单这一道。**
- 不在清单里的组照旧 403，`message` 会写明「这组接口没有对名单以外的地址开放；管理员可在控制台「访问令牌」页……打开」。
- 自查接口 `/me` 不单列：清单里至少有一组真的开放时随之开放。
- 清单里每一条先去掉首尾空白再认；写了没登记的组名（插件卸了、写错了）或写法不合规的不起作用，也不报错；
  设置页上写法不对的组名（大写、中间带空格之类）不让保存，提示只说第几行、不复述原文。
- 在「访问令牌」页点开关保存时，先把整份清单整理干净再落盘：写法不合规的、没登记的直接清掉（只报清掉了几条，
  不复述原文），重复的只留一条，再加上或去掉这一组。保存要么整体成功（配置文件与运行中一致），要么什么都不改。
- 吊销、过期、账号停用的令牌照样 401，开放与否不影响。

### 控制台关着时

控制台被关掉（`novabot.core.config-ui.enabled: false`）时，这个前缀照常服务，来源名单与按组开放的清单照样生效；
但令牌的签发与吊销都在控制台里，**关着时既签不了新令牌，也吊销不了旧令牌**。这时令牌泄露了：

- 马上收紧「允许访问的来源 IP」（改 `novabot.core.config-ui.allow-ips`），并把那一组从 `novabot.core.config-ui.api-any-source-groups` 里去掉，把拿到令牌的那一方挡在外面；
- 再打开控制台，在「访问令牌」页吊销那一把（或停用所属账号，名下令牌一并吊销）。

### 无效令牌限速

出示了令牌、却没通过校验（不存在、已吊销、已过期、账号已停用或删除、成员此刻登录不了控制台）的请求按来访者计数
（来访者的判法见上文「来源地址」：经本机反向代理进来的按转发头里的真实地址各算各的，认不出地址的那些共用一格）：
同一来源 1 分钟内超过 10 次，之后的**无效**请求回 429 `too_many_requests`，带 `Retry-After`（秒），窗口过了自动恢复。

- 出示**有效**令牌的请求不看这个计数：同一台机器上一个写错令牌的脚本，不会把拿着正确令牌的程序一起挡在外面。
- 这个计数与控制台登录的失败锁定是两份，互不影响。
- 没带令牌的请求直接回 401，不计数。
- IPv4 按单个地址算；IPv6 按 /64 算一个来源（同一个 /64 里换着地址，照样算同一个）。
- 最多记 1 万个来源。满了只删已经过了窗口的、和窗口开得最早的那些，**正在被限的来源不删**：
  刷一大批别的来源，也不能把一个被限的来源提前放出来。表满且全是正在被限的来源时，新来源出示无效令牌会直接收到 429。
- 它不省处理：有效还是无效，要先比对一遍才知道，被限的请求照样比对，只是回 429 而不是 401。
  它管的是日志不被刷满（一个窗口只记第一次与开始被限的那一次），以及让调用方知道该停下来查令牌。
- 事件流首帧里出示的访问令牌另有一份计数，见下文「事件流」。

## 返回格式

成功响应通常是 `application/json`。取本机图片成功时直接返回原始字节，内容类型见响应头。
所有错误都返回统一的 JSON 格式和对应的 HTTP 状态码。

成功：

```json
{"ok": true, "data": { ... }}
```

失败：

```json
{"ok": false, "error": {"code": "unauthenticated", "message": "访问令牌无效或已吊销"}}
```

`code` 是给程序分辨用的稳定英文代码，`message` 是给人看的中文说明（措辞可能调整，不要按它分派）。

列表类接口的 `data` 统一是：

```json
{"items": [ ... ], "next": "<游标>"}
```

没有下一页时 `next` 为 `null`（字段一定在）。取下一页时把 `next` 原样作为查询参数 `cursor` 带回去。

所有响应都带 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`，
不带任何跨域放行头（浏览器页面里的脚本跨域调不了这个前缀）。

## 错误代码

| HTTP | `error.code` | 什么时候 |
|---|---|---|
| 400 | `bad_request` | 路径写法不对（含分号、反斜杠、编码过的斜杠、`.`／`..` 段；各段解码之后是 `.`、`..`，或含斜杠、反斜杠、控制字符，例如 `%2e%2e`、`%0a`），请求体无法解析为对象，参数不对 |
| 401 | `unauthenticated` | 没带令牌；令牌不存在、已吊销、已过期；所属账号已停用或已删除；所属账号是成员而成员此刻登录不了控制台 |
| 403 | `source_not_allowed` | 来访者不在「允许访问的来源 IP」名单里，请求的这组接口也没有对任何地址开放 |
| 403 | `insufficient_scope` | 令牌有效，但没勾这个接口要求的范围 |
| 403 | `forbidden` | 接口要的是「仅管理员」的范围，而令牌所属的账号此刻不是管理员；其余的权限不足（由具体接口说明） |
| 404 | `not_found` | 没有这个接口；或要的对象不存在、对这个令牌不可见（两者回同样的话） |
| 405 | `method_not_allowed` | 地址对，请求方法不对 |
| 409 | `conflict` | 对象此刻的状态不允许这样做 |
| 429 | `too_many_requests` | 同一来源连续出示无效令牌太多次，见上文；或某组接口给调用方定的量用完了（例如下文「推送」的限量） |
| 500 | `internal_error` | 服务端处理出错（处理器抛了异常或 `Error`、返回值转不成回包），回包是固定的一句话，没有堆栈与内部路径，详情只在服务端日志里 |
| 502 | `delivery_failed` | 只用于下文「推送」：消息交给了发送去向，去向明确说没发出 |

401 响应带 `WWW-Authenticate: Bearer realm="NovaBot"`。429 响应带 `Retry-After`（秒）。

## 范围

范围是令牌能做哪一类事的开关，由插件登记（标识形如 `report:read`，另有中文名和一句说明），
签发令牌时在控制台逐项勾选。接口各自写明要哪一项范围，令牌没勾就回 403 `insufficient_scope`。
范围只收窄、不放大：勾了范围，成员的令牌仍只看得见自己名下的主播。

有的范围标着**仅管理员**：成员签发时勾不了（签发页上置灰并说明，接口上回 403）；
调用时还按令牌所属账号**此刻**的角色再核一次——管理员被改成成员之后，这个账号以前签的带这种范围的令牌，
调要这项范围的接口回 403 `forbidden`，别的范围照常。

不勾任何范围的令牌只能调自查接口 `/me`。签发页列出的范围随已安装的插件而定。

随核心提供、不靠哪一家插件的范围：

| 范围 | 中文名 | 仅管理员 | 用在哪 |
|---|---|---|---|
| `push:send` | 发送推送消息 | 是 | 本前缀下的「推送」一组，见下文「推送」 |
| `events:read` | 读取事件流 | 是 | **不在本前缀下**：事件输出 `/nova/events` 的首帧认证，见下文「事件流」 |

插件登记的范围（例如外发箱的 `outbox:read`、`outbox:deliver`）见各组的说明。

## 成员的令牌看得到什么

- 管理员（含本地管理员）的令牌：全部主播。
- 成员的令牌：只有管理员分给这个成员的那几位主播，判法与控制台给成员过滤主播是同一段代码。
  别人的主播对它来说「不存在」，按 404 回，不透露那位主播在不在。

## `GET /nova/api/v1/me`

任何有效令牌都能调，不要求范围。

```bash
curl -H "Authorization: Bearer nvb_..." http://127.0.0.1:7827/nova/api/v1/me
```

```json
{
  "ok": true,
  "data": {
    "account": {"id": "local-admin", "displayName": "本地管理员", "role": "ADMIN"},
    "token": {"id": "5a17c0de00000001", "name": "备份脚本", "scopes": [], "expiresAt": null},
    "streamers": [
      {"platform": "bilibili", "uid": 123456, "name": "示例主播"}
    ]
  }
}
```

- `account.role`：`ADMIN` 或 `MEMBER`。
- `token.id` 是令牌的编号，与控制台列表里那一行对得上；它不是令牌本身，也推不出令牌。
- `token.expiresAt`：到期时刻（ISO 8601，UTC），不过期为 `null`。
- `streamers`：对这把令牌可见的主播，含已停用的；名字取不到时为 `null`。

## 外发箱

外发会话是管理员为投递通知登记的去向。安装「外发」插件后，签发页会出现 `outbox:read`（读取记录、图片和会话）和
`outbox:deliver`（认领、报告发送结果）两个范围。完整取件流程需要两者。卸载插件后，有效令牌访问这些路径会收到 404，签发页也随之移除这两项。

以下路径均接在部署前缀后面。通用错误见上文「错误代码」，包括 401（账号停用、令牌吊销等）、403（来源或范围不符）和 429（无效令牌限速）。
对于下面带 `{id}` 的接口，编号不存在和主播对调用者不可见会收到相同的 404 `not_found`。

### `GET /nova/api/v1/outbox/messages`

需要 `outbox:read`。记录按编号升序，只列调用者可见的主播。三个查询参数均可省略。

| 参数 | 取值 |
|---|---|
| `status` | 默认 `PENDING`（待发）。还可指定 `SENDING`（发送中）、`SENT`（已发）、`FAILED`（没发成）、`SKIPPED`（跳过）、`UNKNOWN`（结果不明）、`EXPIRED`（过期未发）、`LIMITED`（超限未入箱）、`VOID`（已作废）。 |
| `cursor` | 上一页最后一条返回记录的十进制编号。首页省略或填 `0`。下一页只取编号严格大于游标的记录。 |
| `limit` | 每页 1 至 100 条，默认 20。 |

例如，`?status=PENDING&limit=1` 可以返回如下结果。

```json
{
  "ok": true,
  "data": {
    "items": [{
      "id": 41, "status": "PENDING",
      "createdAt": "2026-06-01T09:00:00Z", "expiresAt": "2026-06-01T09:10:00Z",
      "conversation": {"id": 3, "name": "早班"},
      "streamer": {"platform": "live", "uid": 101, "name": "青山"},
      "kind": "LIVE_ON", "atAll": true,
      "segments": [
        {"type": "TEXT", "text": "开播了"},
        {"type": "IMAGE_BYTES", "index": 1, "byteCount": 8388608,
         "url": "/nova/api/v1/outbox/messages/41/images/1"},
        {"type": "IMAGE_URL", "url": "https://media.example.org/cover.png"}
      ]
    }],
    "next": "41"
  }
}
```

`createdAt` 和 `expiresAt` 是 UTC 时刻（ISO 8601）。`conversation` 保存入箱时的会话编号和名称。
`streamer` 中未取得的信息为 `null`。`kind` 是推送种类，`atAll` 表示原通知是否要 @ 全体。
按 `segments` 数组顺序处理各段。`IMAGE_BYTES.url` 是本机取图路径，包含部署前缀，需要带读取令牌。
`IMAGE_URL.url` 是原图网址，访问外站时不要带 NovaBot 的令牌。

本机图片文件不可读时，列表、单条记录和认领响应都保留该段的下标和取图地址，`byteCount` 为 `null`。仅在这种情况下返回 `unavailable: true`。

```json
{"type":"IMAGE_BYTES","index":1,"url":"/nova/api/v1/outbox/messages/41/images/1","byteCount":null,"unavailable":true}
```

有下一页时保持相同的 `status`，把 `next` 原样作为 `cursor` 带回。
翻页期间新入箱的记录编号更大，会出现在后续页。当前已到末页时 `next` 为 `null`。
未知状态、无效游标、无效页长均返回 400 `bad_request`。

### `GET /nova/api/v1/outbox/messages/{id}`

需要 `outbox:read`。`id` 为记录编号。成功时 `data` 直接给出一条记录，字段与列表中的条目相同。
这个接口可以查询已经认领或已结束的记录。

```json
{
  "ok": true,
  "data": {
    "id": 42, "status": "PENDING",
    "createdAt": "2026-06-01T09:01:00Z", "expiresAt": "2026-06-01T09:11:00Z",
    "conversation": {"id": 3, "name": "早班"},
    "streamer": {"platform": "live", "uid": 101, "name": "青山"},
    "kind": "LIVE_ON", "atAll": false,
    "segments": [{"type": "TEXT", "text": "开播提醒"}]
  }
}
```

### `GET /nova/api/v1/outbox/messages/{id}/images/{index}`

需要 `outbox:read`。`id` 为记录编号，`index` 是段在整条通知中的下标，从 0 开始。
成功时 HTTP 200 的响应体就是入箱的图片字节。例如，上面第 41 条的第 1 段是一张 PNG，取图响应开头如下（正文仅示前八字节，以十六进制表示）。

```text
Content-Type: image/png
Content-Length: 8388608
Cache-Control: no-store
X-Content-Type-Options: nosniff

89 50 4E 47 0D 0A 1A 0A
```

无法识别图片格式时使用 `application/octet-stream`。下标越界、指向文字或网址图片段、本机图片文件丢失或不可读，均返回相同的 404 `not_found`，错误正文仍为 JSON。

### `POST /nova/api/v1/outbox/messages/{id}/claim`

需要 `outbox:deliver`。`id` 为待发记录编号，无需请求体。成功时记录进入 `SENDING`，认领者记为令牌名称。
`data.message` 是认领后的记录，`data.claimNumber` 是这条记录本次认领的编号。

```json
{
  "ok": true,
  "data": {
    "claimNumber": 1,
    "message": {
      "id": 42, "status": "SENDING",
      "createdAt": "2026-06-01T09:01:00Z", "expiresAt": "2026-06-01T09:11:00Z",
      "conversation": {"id": 3, "name": "早班"},
      "streamer": {"platform": "live", "uid": 101, "name": "青山"},
      "kind": "LIVE_ON", "atAll": false,
      "segments": [{"type": "TEXT", "text": "开播提醒"}]
    }
  }
}
```

并发认领只有一个请求成功。其余请求以及对过期、已发、作废等非待发记录的认领返回 409，说明里给出当前状态。以下是已被认领时的响应。

```json
{"ok":false,"error":{"code":"conflict","message":"记录当前为「发送中」，无法执行此操作"}}
```

### `POST /nova/api/v1/outbox/messages/{id}/receipt`

需要 `outbox:deliver`。`id` 为记录编号。以 `application/json` 提交一个对象，带上本次认领返回的正整数
`claimNumber` 和 `outcome`（`SENT` 已发、`FAILED` 没发成、`SKIPPED` 跳过）。
`note` 为可选说明，允许省略、空字符串或 `null`，最长 200 个 Unicode 码点。以下请求把通知标记为已发。

```json
{"claimNumber":1,"outcome":"SENT","note":"已送达早班会话"}
```

成功响应给出记录编号和已保存的结果。

```json
{"ok":true,"data":{"id":42,"status":"SENT"}}
```

正文为空或无法解析为对象（例如数组、无法解析的文本）时，返回 400 `bad_request`。解析器接受单引号和对象末尾多出的逗号。
正文超过 256 KB、必填字段缺失、字段类型或结果不合法、说明超长也会返回 400 `bad_request`。
记录为 `SENDING` 或 `UNKNOWN` 且认领编号与本次认领一致时，接受结果并更新状态。
记录未认领、已经有最终结果或认领编号过时，返回 409 `conflict`，提交的结果不会覆盖当前状态。

### `GET /nova/api/v1/outbox/conversations`

需要 `outbox:read`，无参数。一次列出全部会话，按编号升序，可用 `id` 核对当前名称和备注。
`enabled` 为 `false` 表示会话已停用。停用只挡住新通知入箱，已有的待发通知仍可认领。

```json
{"ok":true,"data":{"items":[{"id":3,"name":"早班","remark":"日间通知","enabled":false}],"next":null}}
```

### 取件方应当怎么用

1. 定时从首页列出待发通知，沿 `next` 翻到末页。下一轮从首页重新列，以便发现管理员重新放回待发的旧编号。
2. 按编号认领。只有收到成功响应才处理通知，保存这次的 `claimNumber`。认领返回 409 时跳过该条。
3. 按段顺序准备文字和图片，通过 `IMAGE_BYTES.url` 取回本机原图。发送前核对 `expiresAt`，已过期就跳过并报告 `SKIPPED`。
   若图片段带有 `unavailable: true`，或取图时收到 404，用本次 `claimNumber` 报告 `FAILED` 或 `SKIPPED`，然后继续处理下一条通知。
   若取图时连接失败、超时、断开，或收到 5xx、429，可以保留认领并在到期前重试。到期仍未取到图片时，可报告 `FAILED` 并在 `note` 简述原因。
4. 发出后用本次 `claimNumber` 报告 `SENT`。发送故障可报告 `FAILED` 并在 `note` 简述原因。
   若已发出而报告结果时断线，可查单条记录核对状态，避免重复发送。

认领后默认 15 分钟仍未报告结果，记录会先变成 `UNKNOWN`（结果不明），系统不会自动重发。
在记录保留期间，迟到的回报仍可将这个状态更新为实际结果。管理员在控制台重新放回待发后，原认领的回报失效。
待发通知也可由管理员在控制台作废。

## 推送

外部程序请 NovaBot 代发一条消息用。这一组随核心提供，不靠哪一家插件：NovaBot 里登记了的发送去向
（QQ 机器人通道、QQ 官方机器人、外发等）都能经它发；一个去向也没装时，`platforms` 回空列表。

范围只有一项：`push:send`（发送推送消息），**仅管理员**。成员签发时勾不了，伪造请求去签也回 403；
管理员被改成成员之后，他以前签的带这一项的令牌调下面两条回 403 `forbidden`。两条都要 `push:send`。
令牌只勾了别的范围（例如外发箱的 `outbox:read`）时回 403 `insufficient_scope`。

来源名单与按组开放照底座的规矩：这一组的组名是 `push`，**默认不对名单以外的地址开放**，
与外发箱各管各的——只打开 `outbox` 时，名单以外的来访者调这一组仍是 403 `source_not_allowed`。

### `GET /nova/api/v1/push/platforms`

列出此刻登记了的去向，按 `id` 排序。

```json
{
  "ok": true,
  "data": {
    "items": [
      {"id": "qq-official", "name": "QQ 官方机器人", "targetTypes": ["GROUP"], "enabled": true},
      {"id": "qq-onebot", "name": "QQ", "targetTypes": ["FRIEND", "GROUP"], "enabled": false}
    ],
    "next": null
  }
}
```

- `id`：发消息时填进 `platform` 的标识。
- `name`：控制台上显示的名字。
- `targetTypes`：这个去向能发往的目标种类，`FRIEND`（好友）、`GROUP`（群）。外发只有 `GROUP`，号码填外发会话的编号。
- `enabled`：`false` 表示这个去向此刻被管理员停用（例如在控制台关了机器人通道），往它发会回 409。它不说明连没连上。

### `POST /nova/api/v1/push/messages`

以 `application/json` 提交一个对象：

```bash
curl -X POST http://127.0.0.1:7827/nova/api/v1/push/messages \
  -H "Authorization: Bearer nvb_..." -H "Content-Type: application/json" \
  -d '{"platform":"qq-onebot","targetType":"GROUP","target":"123456789","content":"今晚八点开播"}'
```

| 字段 | 取值 |
|---|---|
| `platform` | 去向标识，取自 `platforms` 里的 `id` |
| `targetType` | `FRIEND` 或 `GROUP`，大写 |
| `target` | 号码：正整数，不带正负号与前导零。收字符串或整数；号码可能超出一些语言的安全整数范围，**建议写成字符串** |
| `content` | 要发的内容，不能为空。写法与平时推送模板相同，`{at=all}`、`{image_url=…}`、`{face=…}` 照常用；`{next}` 不收，一次请求只发一条 |

别的字段不看。发出了：

```json
{"ok": true, "data": {"id": "1984726350", "delivery": "SENT"}}
```

交出去了、没等到明确结果：

```json
{"ok": true, "data": {"id": null, "delivery": "UNKNOWN"}}
```

- `SENT`：去向明确说发出了。`id` 是去向给的消息编号，一律是字符串；去向没给时为 `null`。
  经外发发的，`SENT` 表示已存进外发箱、等取件程序取走，`id` 是外发记录编号。
- `UNKNOWN`：消息交给了去向，但没等到明确结果（例如等回包超时），**可能已经发出**，`id` 为 `null`。
  NovaBot 这一边不会重发，调用方也**不要自动重发**；要核对，去群里看，或查控制台的时间线。
- 含图片的消息图片发不出去时，整条按没发出回 502，**不会**像平时推送那样去掉图片再补发一条纯文字：
  补发出去的是另一条，再回「发出了」就不是实话。
- `{at=all}` 照平时的规矩：机器人没有权限、或当天的额度用完时摘掉再发（时间线上另有一条「未 @ 全体」）；
  摘掉之后没有内容了回 409。

### 出错时

| HTTP | `error.code` | 什么时候 | 发出了没有 |
|---|---|---|---|
| 400 | `bad_request` | 请求体不是 JSON 对象，或超过 256 KB；`platform`、`targetType`、`target`、`content` 缺了或写错（说明里写着是哪一项）；`content` 是空的或含 `{next}`；这个去向不能发往这种目标（例如对只收群消息的去向发 `FRIEND`） | 没发 |
| 401 | `unauthenticated` | 没带令牌、令牌无效、已吊销、已过期等，与底座一致（无效令牌照常计限速） | 没发 |
| 403 | `source_not_allowed` | 来访者不在名单里，`push` 这组也没对任何地址开放 | 没发 |
| 403 | `insufficient_scope` | 令牌没勾 `push:send` | 没发 |
| 403 | `forbidden` | 令牌所属的账号此刻不是管理员 | 没发 |
| 404 | `not_found` | 没有这个去向（`platform`）；说明里不复述你填的值 | 没发 |
| 409 | `conflict` | 去向此刻已停用；去向此刻连不上（消息没交到它手里）；摘掉发不出的 `@全体成员` 之后没有内容 | 没发，可以稍后再试 |
| 429 | `too_many_requests` | 这把令牌一分钟内的发送已到 600 条，带 `Retry-After`，见下文「限量」 | 没发 |
| 502 | `delivery_failed` | 去向明确说没发出：号码写错、机器人不在这个群里或不是对方好友、内容不被接受等 | 没发 |
| 500 | `internal_error` | 服务端处理出错 | **说不准**：不要自动重发，查控制台的时间线 |

`message` 都是写死的话：不带去向回包里的原话、内部异常与口令，也不复述请求里的原文。
去向给的原因记在控制台的时间线上，给管理员看。调用方与 NovaBot 之间断了线、等不到回包时，
同样说不准发没发出，同样不要自动重发。

走 HTTP 投递的去向（配置文件里写着推送地址的那种）怎么算：

- 能确定对方没收到的——连接被拒、找不到主机、连接没建起来——NovaBot 会再试，一共最多 3 次；
  3 次都是这样回 409 `conflict`（连不上），消息没发出。
- 等回包超时、连接中途断开、读回包失败、回包是空的，以及认不出是哪一种的，对方都可能已经收下：
  这一条只交出去 1 次，不再重试，回 `UNKNOWN`。

进程内的去向（各家机器人通道、外发）只在消息没离开 NovaBot 时才算没交到，那时同样最多试 3 次、回 409；
它们自己等回包超时的，回 `UNKNOWN`，不重试。

### 限量

同一把令牌任何一分钟里最多发 600 条，与旧推送接口每分钟 600 条是同一个数。第 601 条起回 429 `too_many_requests`，
带 `Retry-After`（秒）：等到这一分钟里最早那一条满一分钟。

- 按令牌各算各的：一把令牌超了，别的令牌照常能发。
- 计的是对 `messages` 的请求次数，写错被拒的也算；被 429 挡回的不算，一直刷不会越等越久。`platforms` 不计。
- 只记在内存里，重启清零。
- 它与底座的「无效令牌限速」是两回事：那一道按来源数无效令牌，这一道按令牌数发送。

### 与全局推送开关、静音时段的关系

这是调用方明确要发的一条，所以与旧推送接口（`POST /onebot/send`）一样，**不受「全局推送开关」与静音时段管**：
首页按了「暂停全部推送」、正处在静音时段，照发。**去向本身被停用时不发**（例如管理员在控制台停了机器人通道），回 409。

### 时间线上记什么

每一次经这组接口的发送（发出了、没发出、不明都算）都在控制台的事件时间线上记一条，归在「推送」里：
发出了记「推送成功」，没发出记「推送失败」，不明记「送达不明」。写明哪个账号的哪把令牌、发往哪个去向的哪类目标，例如：

> 程序接口发出一条消息：令牌「告警转发脚本」（值班管理员）→ QQ 群 12…89

- 号码只留头尾两位，四位以内的整个省掉；正文不记，只记字数；令牌只记名字与编号，令牌本身不进时间线、日志与回包。
- 没发出时补一项去向给的原因（遮掉在用的凭据与这次的号码，截到 120 字）。
- 这些记录不挂主播，成员的时间线里看不到。
- 一把令牌被限量时，只在开始被限的那一次记一条。
- 请求体写错（400）、没有这个去向（404）这类没走到发送那一步的，不记。
- 它们计入首页「今天推成功／推失败」的条数，但不进推送页「本群最近推送」，也不左右推送健康的判断。

### 与旧推送接口

`POST /onebot/send` 原样保留：路径、每个机器人一把的推送口令、它自己的来源名单与限速、回包都不变。
新接入的程序建议用这一组：按账号签发、能随时吊销、权限跟着账号走、每一次都记在时间线上，而且发得了所有登记了的去向。

## 事件流

事件输出（把直播间事件实时推给外部面板的那条 WebSocket 长连接）**不在 `/nova/api/v1/` 下**：
本前缀是一问一答的，接不了长连接，所以它仍在 `/nova/events`，连接方式、事件格式见
[事件源协议](protocol.md)。这里只说访问令牌怎么用在它上面。

- 范围是 `events:read`（读取事件流），**仅管理员**：一条事件流里是全部主播的事件，不按账号分。
  成员签发时勾不了，伪造请求去签也回 403；成员的令牌连不上事件流。
- 令牌出示在连接建立之后的第一帧 `{"kind":"auth","token":"nvb_..."}`，与只读口令同一个位置、同一种回应。
  不认 `Authorization` 头、子协议与查询参数：带了这些的握手照旧回 HTTP 400。
- 认的是：勾了 `events:read`、未吊销、未过期，所属账号此刻启用着、是管理员。没勾这一项的令牌（例如只勾了
  `outbox:read` 或 `push:send`）回 `auth_failed`（`bad_token`），与出示一串从没签发过的字符一样，看不出令牌在不在；
  勾了的，已吊销回 `revoked`，已过期回 `expired`，所属账号此刻不是管理员回 `bad_token`。
- 连着的时候令牌被吊销或到期、所属账号被停用、删除或降为成员，这条连接会被关掉：
  在控制台吊销、停用、删除、改角色时当场断开；到期由每 15 秒一轮的复核发现，到期后十几秒内断开。
- **只接受本机连接**，与来源名单（`allow-ips`）、「从别的机器访问」里的逐组开关都无关：打开哪一组都不会让外面的机器连得上事件流。
  别的机器要读，用 SSH 隧道。
- 首帧里访问令牌认证失败有自己的一份计数（不与本前缀的「无效令牌限速」共用）：本机 1 分钟内失败满 10 次后，
  这一分钟余下的时间里出示访问令牌的连接不核对，按「暂忙」关闭（关闭码 `1013`），客户端照常退避重连即可。只读口令不计入。
- 日志里记的是哪个账号的哪把令牌（名字与编号），不记令牌本身。连上之后，控制台列表里这把令牌的「最后使用」会跟着更新。
- 旧的只读口令（控制台「连接 → 外部面板」签发）照常能用，签发、吊销与连接行为都不变。

## 访问令牌的保管

- 落盘只有令牌的 SHA-256 摘要（运行状态文件 `state.json` 的 `api-tokens` 一段），没有明文；
  比对用常量时间。明文只在签发那一刻显示一次，遗失了只能吊销再签。
- 控制台列表、操作记录、日志里只出现令牌的编号，不出现明文，也不出现摘要。
- 每个账号最多 20 把有效令牌（已吊销、已过期的不算）。名字可以重复。
- 签发、吊销都记进控制台的操作记录（动作 `API_TOKEN_ISSUE`、`API_TOKEN_REVOKE`，对象里是令牌编号与所属账号）。
  停用、删除账号时一并吊销的，记在那一条（`ACCOUNT_DISABLE`、`ACCOUNT_DELETE`）的对象里，只有把数 `revokedTokens`。

## 插件怎么挂接口

插件实现 `org.frostnova.nova.core.api.NovaApiProvider` 并注册为 Bean：

```java
@NovaComponent
public class ReportApi implements NovaApiProvider {
    @Override public String segment() { return "report"; }

    @Override public List<NovaApiScope> scopes() {
        return List.of(new NovaApiScope("report:read", "读取直播报告", "读取各场直播报告的数据"),
                NovaApiScope.adminOnly("report:rebuild", "重算全部报告", "按现有数据重算所有主播的直播报告"));
    }

    @Override public List<NovaApiRoute> routes() {
        return List.of(NovaApiRoute.get("streamers/{platform}/{uid}/latest", "report:read", request -> {
            long uid = Long.parseLong(request.path("uid"));
            if (!request.caller().canSee(request.path("platform"), uid)) {
                throw NovaApiException.notFound("没有这位主播");
            }
            return Map.of("uid", uid);
        }), NovaApiRoute.post("rebuild", "report:rebuild", request -> Map.of("queued", true)));
    }
}
```

**全实例的操作用「仅管理员」的范围，按主播的数据用 `canSee`。**

- 动的是整个实例（改全局设置、重算所有主播的东西、看全局的运行状态）：把范围登记成仅管理员——
  `NovaApiScope.adminOnly(id, 中文名, 说明)`，或 `new NovaApiScope(id, 中文名, 说明, true)`。
  成员签不出带它的令牌，管理员降成成员后旧令牌也调不动它，这两件底座都替你核了，处理器里不用再判角色。
- 按主播划分的数据（某位主播的报告、场次、观众）：范围照常登记成人人可勾，处理器里用
  `request.caller().canSee(platform, uid)` 逐个筛——成员只见名下的，管理员全部可见。
  别为了「成员不该看别人的主播」把范围标成仅管理员：那样成员连自己名下的也看不了。

- 鉴权、来源名单与按组开放、无效令牌限速、范围核对（含仅管理员）、返回格式与错误包装都由底座做；
  处理器拿到的 `request.caller()` 是已认证的调用者：账号编号、显示名、角色、令牌名与范围，
  以及 `canSee(platform, uid)`——某平台某主播对这个调用者是否可见（管理员全部可见，成员只见名下）。
  `hasScope(id)` 说的是「此刻用得了」：仅管理员的范围，账号此刻不是管理员时为 false。
- 处理器返回的对象放进 `data`；列表接口返回 `NovaApiPage.of(items, next)`；
  图片等原始字节返回 `new NovaApiBytes(MediaType.IMAGE_PNG, bytes)`，底座直接按指定内容类型写出。
  要回错误就抛 `NovaApiException`（`badRequest`、`forbidden`、`notFound`、`conflict`，或自定状态码与代码）；
  给调用方定了量、量用完时抛 `NovaApiException.tooManyRequests(说明, 秒数)`，回包是 429 并带 `Retry-After`。
  抛别的异常（含 `Error`）、或返回的对象转不成 JSON，一律回 500 `internal_error`，异常内容不进响应，只进服务端日志。
- 路径变量拿到的是解码之后的值；`.`、`..`，或含斜杠、反斜杠、控制字符的段到不了处理器，底座先回 400。
- 可以另写 `name()`（这组接口的显示名，如「外发箱」）与 `description()`（一句说明）：控制台「访问令牌」页
  逐组列出、让管理员决定哪一组对任何地址开放时用。不写时显示段名。
- 段名、范围标识、接口路径的写法有规矩（小写字母开头；路径变量写成 `{name}`），
  每个接口要求的范围必须是本插件自己登记的。登记不合规的那一家整个不予采用，日志里点名说明，程序照常启动。
- 范围标识不能与底座自带的重名（例如 `events:read`）：重名也算登记不合规。
