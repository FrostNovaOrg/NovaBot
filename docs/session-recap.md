# 场次事实与跨场规律

`SessionRecapService.calculate(platform, uid, startTime)` 位于 `nova-core`，只读取已经建立的观众账本与归档，不更新账本。调用方应先调用 `AudienceLedgerService.updateStreamer`。未入账的目标场次返回空结果，读取账本或事件失败会抛出异常。

样稿需要多场时可调用 `calculateBatch(platform, uid, starts)`，返回与输入顺序对应的 `List<Result>`；重复时刻保留，未入账的时刻返回空结果，空输入返回空列表。单场入口共用同一套计算。批量只扫描一次截至最后一个已入账目标的账本，在各目标处生成独立结果，不使用该目标之后的数据。

计算按时间顺序读取账本所需字段，历史扫描跳过昵称、礼物明细等无关内容。每位观众使用基本类型数组保存出现状态，仅保留最近五场名单和三个尚未成熟的新人批次，缓冲区循环复用。场次归档只投影时刻与指标，不保留全历史观众名单；事件计算在一次调用内共用读取缓冲区与逐场汇总，不建立跨调用缓存。展示昵称另按本场需要点名的少数编号读取，不建立全历史昵称表。

结果类型是 `analytics.SessionRecap.Result`，包含 `facts` 与 `patterns`。计算返回全部达到条件的规律候选，后续展示方再选至多两条；这里不生成文字或发送消息。

每个 `Item` 包含 `key`、`streamer(platform, uid)`、`session`（目标开播毫秒）、`values`、`sample(sessions, from, qualifiedSessions)`、`people`、`evidence(path, selector)`。`strength` 仅规律有值，事实为 null。金额为元，比例为 0–1，时刻为毫秒。`from` 是实际使用场次的最早开播毫秒，证据路径相对直播归档根目录。涉及新人识别的样本包含此前用于排除已见观众的全部账本场次；`qualifiedSessions` 单独计其中的合格场次，供模板的样本标题使用。

## 共同规则

所有场次先截断到目标开播时刻，再做分组、取最近场次、判断样本成熟。合格场次同时要求账本 `qualified=true` 与 `listQuality=complete`。主播本人、编号零与当前拒绝名单中的人不会进入观众计数或名单。名单不完整的场次仍提供“此前已经见过此人”的证据，但不产生新人批次，也不参与回流窗口、常客或时段与 PK 规律。

目标之前账本不到十场时，不产生新人或回流结果；历史新人批次也要在各自开播前已有十场记录。新人判断检查此前所有账本场次，而不限于合格场次。零是已知结果时可以输出；字段、事件文件或分母缺失时不填假零。

## 事实

| key | 计算 |
| --- | --- |
| `duration` | `sessions.jsonl` 的 `startTime`、`endTime`、`durationSeconds / 60`，分别为 `start`、`end`、`durationMinutes`。结束时刻或时长无效则省略。 |
| `watched_rank` | 主播页直接展示的归档指标 `watched_count`，输出 `watched`；在截至目标最近十个合格场次中，`rank=1+严格大于本场的场数`，并列同名次；`outOf` 是该窗口有此指标的场数。目标不合格时仍可与这个窗口比较，但目标不加入窗口。 |
| `gift_rank` | 同上，直接取主播页的 `gift_value` 为 `gift`；不加醒目留言、大航海、付款或盲盒盈亏。 |
| `newcomers` | 目标须合格且记录足够。当前观众此前从未入账的人数为 `newcomers`，其中 `spoke=true` 的人数为 `newcomerSpoke`。 |
| `fan_club` | 明细 `gifts` 按名字精确匹配“粉丝团灯牌”，累加 `count` 为 `fanClub`；没有匹配项不出。 |
| `follows` | 当前 `events.jsonl` 中 `t=follow` 的行数为 `follows`。文件存在且为空时为零，文件缺失时不出。 |
| `returning_newcomers` | 上一合格场次中开口的新人总数为 `previousSpoke`，与当前合格场次观众求交集为 `returned`，交集编号升序放在 `people`。上一场记录不足时不出。 |
| `top_gifters` | 明细 `rankings.gift_users` 先过滤主播与拒绝名单，再按金额降序、编号升序取前三。编号放 `people`，对应金额列表放 `values.gift`，顺序一一对应。 |
| `top_words` | 明细 `words` 按频次降序、同频按词升序取前三，词列表放 `values.words`。 |

前三项与排名都使用原有归档字段；灯牌、礼物榜、热词读取的 `LiveDetail` 与归档报告图共用。关注按事件行计，不用关注观众去重数替代。

## 规律

| key | 计算与样本 |
| --- | --- |
| `newcomer_speak_return` | 只纳入截至目标已完整观察后续三个合格场次的新人批次，每位新人只计一次。开口组回流人数/开口人数为 `spokeReturn`，未开口组同理为 `silentReturn`；人数为 `spokeN`、`silentN`。开口组至少三十人。`todayRate` 是本场新人开口比例；`usualRate` 是目标之前最近十个合格场次中已知且新人分母非零的开口率中位数。本场无新人、未开口组无人或没有可计算的平时开口率时，不输出无法比较的规律。 |
| `slot_compare` | 按东八区开播小时除以六分四段，选择场数最多的两段，同场数按时段先后。各至少三场，所有入选场次的看过与礼物指标都已知。`slotA/B` 为凌晨、上午、下午、晚上之一；`sessionsA/B` 为场数，`watchedA/B` 与 `giftA/B` 为各自中位数。 |
| `pk_share` | 按事件 `pk` 编号配对 `pk_open` 与 `pk_settle`，区间含开不含结算，截在开播与下播之间，重叠区间合并。分别累加 `gift/box/guard` 的 `val`，除以对应区间总分钟数，得 `pkGiftPerMin` 与 `normalGiftPerMin`。非 PK 分母也包含有完整事件记录的无 PK 合格场次。至少三个场次有 PK，数量为 `pkSessions`；事件文件缺失或有未结算 PK 的场次不参与比较。 |
| `regulars_absent` | 截至目标最近五个合格场次之前的合格场次为历史段，出现至少三场且占历史段至少四成者为常客，人数为 `regulars`。其中最近五场全没出现者为 `absent`，名单按历史出现场数降序、同场数按编号升序。常客至少十人；目标不合格时最近五场取此前合格场次。 |

中位数在偶数样本时取中间两数的平均数。强度先检查任一组是否不足门槛两倍，是则 `weak`；否则比较两组数值，大值至少为小值两倍且大值非零则 `strong`，其余为 `medium`。两组均零是 `medium`，正数对零是 `strong`。新人按两组人数、门槛三十比较回流率；时段按两段场数、门槛三比较看过中位数；PK 按有 PK 场数、门槛三比较分钟礼物。常客先以十人的两倍判断 `weak`，再判断缺席是否至少一半，分别为 `strong` 或 `medium`。

未完整观察三场的新人批次整体暂不进入回流率，避免仅纳入已经回来的新人造成比例偏高。已知数据不足以求比例、指标缺失或 PK 未结算时省略对应规律，保留其余可算结果。`trying_delta` 尚未实现。

## 私聊小结模板

`analytics.SessionRecapRenderer.render(result, options, history)` 是纯函数，不读取文件、不调用模型、不发送消息。`Options(level, showAmount, nicknames)` 接受档位 1 或 2、金额开关与 `Nicknames.ORIGINAL / MASKED`；可用第四个参数传当前拒绝名单，与计算结果中保存的拒绝名单合并过滤。`Result.presentation` 提供本场开播时刻、此前记录数、名单质量、上一合格场次日期、展示昵称、拒绝名单快照及热词昵称归属。热词匹配所需的昵称从本场 `detail.json` 的全部排行榜名单临时提取，包括未被点名和拒绝名单中的观众；只保留匹配到热词的昵称与编号，不落盘、不进入观众账本或去重记录。旧的二参数 `Result` 构造器仍可用，但没有这些展示信息时无法点名或生成名单质量提示。

返回的 `Draft.lines` 是消息各行，`Line.keys` 是来源键；`notes` 只供管理员查看，`message()` 仅拼接正文。看过与礼物的合并行标记两个键，规律段标题标记所选规律的键，其他行各标记一个键。`Draft.history` 保存这次的场次和实际说出的规律；调用方应在消息使用后保存它，下一次传回。未选出规律的小结也应保存空记录，以便按最近三次小结去重。金额关闭时，保存的时段规律也不含礼物数值。

第 1 档最多八行，顺序是标题、看过与礼物、新人、灯牌、关注、回来的新人、礼物前三、热词。灯牌与关注各占一行，保持事实来源独立。标题按东八区开播小时分凌晨（0–6）、上午（6–12）、下午（12–18）、晚上（18–24），不足一小时用分钟，整小时不追加零分钟。缺失数据和零值统计省略；日期、时间及排名窗口中的数字正常显示。回来人数会按再次过滤后的名单计数，名单最多展示三个昵称，人数多于列出的昵称数时加“等 N 位”（包括昵称缺失的情况）；未知昵称不以编号代替。

排名只展示至少五场已知指标中的前三名。名次写实际参与排名的场数，例如“最近 7 场第 2”。看过与礼物同名次且参与场数相同时合写，不同则分别标注，不提供倒数。关闭金额后，礼物金额、礼物榜、PK 规律和时段规律中的金额均不出现。金额沿用下播报告图的写法：四舍五入到一位小数，去掉末尾小数零，例如 269.00 显示 269、0.30 显示 0.3、1.666… 显示 1.7；舍入为零的金额省略。打码按完整字形切分（包括表情、国旗与组合表情），单字形昵称全部换成 `*`，两个及以上字形保留第一个，其余换成最多两个 `*`，例如“甲”显示“*”、“观众甲”显示“观**”。热词与单字形昵称完全相同时才匹配，两个及以上字形的昵称仍按热词中的部分匹配；匹配到展示昵称或本场明细名单昵称的部分也打码。按同样规则匹配到拒绝名单昵称的热词整条省略；同名观众中有一位在拒绝名单也省略该热词。例如昵称“哈”只匹配热词“哈”，不影响“哈哈哈”；昵称“观众乙”仍匹配“观众乙来了”。昵称、热词含换行或因果措辞时不采用。

第 2 档至多追加两条规律，先按强、中、弱排序，同强度按 `newcomer_speak_return`、`regulars_absent`、`slot_compare`、`pk_share` 排序。句式使用固定的回流率、缺席人数、时段中位数或每分钟礼物比较，比例固定一位小数；比较所需数值缺失、为零或比例舍入后为零时省略该条或金额分句。弱规律句末加“样本还少，先当参考。”标题“从你过去 N 场里看到的”取所选规律最大的合格场次数，没有规律时整段省略。

同一规律在目标场次之前最近三次小结中说过时，和最近一次说出的值比较：两组大小严格翻转，或主要数值相对旧值变化严格超过一半，才再次展示。主要数值分别是开口组回流率、缺席人数、第一时段看过中位数、PK 每分钟礼物；旧值为零时，正值视为变化过半。常客的两组是缺席与其余常客；时段按名称对齐后比较，交换顺序不视为翻转，比较时段组合不同视为另一条规律；每个组合单独和最近三次小结中该组合最近一次说出的值比较。开启金额时，时段礼物的大小翻转也可重说。礼物差距以较小值为分母，严格不到两成时说“礼物差不多”。

管理员注按名单质量写“未登录采集”“不确定”“没有名单”，提醒本场新人、回来类没有统计；此前记录不足十场时说明没提新观众。选出新人开口回流规律时，附注提醒这只是一同出现的现象，不能据此认定开口让人回来。管理员注不进入消息正文。

只有不去重时原本会排进前两条、却被最近三场去重压下的规律，才在管理员注中写“这条规律 3 场内说过，这次没说”。


## 私聊投递

推送通道中勾选「这是主播本人」后，才能开启默认关闭的「下播小结（私聊）」。
只有好友通道可开启；取消本人标记会同时取消这项订阅。下播报告图的推送保持原有设置。

服务启动时检查一次，之后每五分钟检查。只处理已封存的最终场次，到点为结束后 30 分钟；
续播撤销封存，真下播后重新计算。静音按该通道设置顺延。开启订阅前已经结束的场不补发，
不足 10 分钟、未正常关闭、档案暂停或全局推送关闭时不发；已经再开播、有更新封存场次，
或到点超过 24 小时则作废。档案暂时读不出会在下一轮重读，坏件恢复后仍可继续投递未过期的小结。

正文按主播档案的档位与「别提」、通道金额设置和观众拒绝名单渲染。昵称使用原名，
管理员注不发送。此前已发送或送达不明的场次共同参与规律去重。

从未自己选过档位的主播默认按第 2 档发送，有规律时附上规律段；不回招呼也按这一档发。
旧档案中第 1 档且 `tierSetAt` 为空的，读取时也按第 2 档处理，不会当作坏件。
`tierSetAt` 有值时保留主播选的第 1 或第 2 档，也不再发选档招呼；随时回「改成 1」仍可切换到只要小结，
回复招呼选择 1 也一样，两种方式都会记录设定时刻。

发送记录位于直播数据文件同目录的 `session-recap-deliveries.json`，仅属主可读写，保留 90 天。
其中 `subscriptions` 保存订阅开启时刻；`records` 每个订阅、每场一条，包含订阅标识、开播与到点时刻、
状态、原因、更新时间和渲染返回的规律记录，不保存正文或观众昵称。发送前会保存 `SENDING`，
重启时改为 `UNCERTAIN`；`FAILED` 和 `UNCERTAIN` 都不自动重发。

记录文件损坏时，原文件会另存为 `.bad-时间`，同时留下 `.unreadable` 标记，暂停自动发送。
应停机后从备份恢复有效的发送记录文件，再启动；服务成功读取后会清除标记。
不要以空文件代替丢失的历史，否则无法核对哪些小结已经送达。

## 开播前提醒（私聊）

「开播前提醒（私聊）」默认关闭，只能在勾了「这是主播本人」的好友通道开启。
群通道或未标本人的好友通道保存时会被拒绝；取消本人标记会一并去掉小结与提醒订阅。

惯常时间取本主播最近十场满十分钟的已封存场次，按 `Asia/Shanghai` 的开播时刻计算。
在首尾相接的一天中，寻找能盖住最多场次的六十分钟窗口（含两端）；至少五场才成立，
取这组最早的时刻作为惯常开播时间。同场数的窗口取钟面上较早的起始时刻。
只在对应开播日期的上周同一天、同一窗口内播过时提醒；跨午夜窗口包含次日的那一段。
提醒在惯常时间前六十分钟，例如惯常 00:20 开播，前一天 23:20 提醒。

服务启动就绪后检查一次，随后每五分钟检查。到点至十分钟内可发，超过十分钟不补。
每条订阅的定时提醒每天最多一条，重启不重发；每天固定时刻按东八区到期日计，跨午夜发送不占次日名额。
惯常时间提醒的十分钟有效期跨午夜且次日才首次发送时，同时登记原提醒日和实际发送日，防止同一提醒重复或同一天再发。
每轮只读取一次封存场次列表，多条订阅共用该列表。

纯文字提醒最多两段，昵称使用原名，每段最多展示三个名字，更多时附「等 N 位」。
「最近没来的常客」直接使用 `regulars_absent` 成立时的缺席名单，按历史出现场数降序排列；
规律不成立或无人缺席时不出现。
「上一场第一次说话的新观众」取最近一场满十分钟的已封存场次，复用 `today.spoken` 的首次出现且开口口径，
按该场发言条数降序、同条数按编号升序排列。该场之前账本不足十场或该场名单不完整时不出现。
计算前会更新观众账本；常客昵称从历史账本由近到远补齐，不使用编号代替缺失昵称。
主播本人和当前拒绝名单中的观众会被排除。「别提老观众」省略第一段，「别提新人」省略第二段。

订阅未开启、主播或通道停用、非本人好友通道、档案暂停或读不出、全局推送关闭、
通道静音、已经在播、两段都没有可展示名字时均不发送。静音使用东八区时刻与通道规则判断。
档案暂时读不出或归档读取失败时本轮跳过，下一轮仍在十分钟内可以重试，过期不补。

发送记录另存于直播数据文件同目录的 `pre-live-reminder-deliveries.json`，仅属主可读写。
文件按订阅标识分别保存日期与状态，不存正文、昵称或观众名单。发送前先保存 `SENDING`，
重启读取时将发送中视作 `UNCERTAIN`；发送失败或结果不明均不会自动重发。
记录无法保存时不发送。记录损坏时保留原件并留下 `.unreadable` 标记，暂停提醒；
停机恢复有效备份再启动后可继续，不能用空文件代替历史记录。

| 开播前提醒改到前 N 分钟／改到前 N 分钟 | 惯常开播前 N 分钟提醒，只收 5–180 分钟 |

| 开播前提醒不要了／不要开播前提醒 | 只关闭开播前提醒，不影响下播小结 |
| 准备开播 | 现在发同样的提醒；没有可展示名字时说明没有要特别留意的 |

时间支持 `19:00`、`19：00`、`7:30`、`19点`、`19点30`，回复统一为两位小时、两位分钟。
提醒设置同其他档案命令一样忽略标点、转换全角数字，例如「开播前提醒，不要了」「改到前３０分钟」。简写「每天」后跟数字加「点」或冒号、「改到前」后跟数字才接作设置；「每天都好累」「改到前面去」照旧交给追问或菜单，像时间但格式错误的仍回用法。
提前量和每天定时互相替换，设置任一种都会解除「不要了」。每天定时仍受暂停、在播、全局开关、
启动就绪、十分钟有效期和一天一条约束，只有通道静音不拦。「恢复」只解除暂停，不撤销「不要了」。
「你记得我什么」会列出默认提前六十分钟、自选提前量、每天定时或「不要了」。

「准备开播」只接受当前确认的主播本人私聊，仍须管理员为这条通道开启提醒订阅。
不看静音、在播、暂停或「不要了」，全局推送关闭时仍不发。发过就算当天的一条，
当天定时不再发；本人再次索取仍可再发。

控制台「推送」页的本人好友通道中，「开播前提醒（私聊）」旁会显示后端生成的状态：
订阅是否勾选、本人当前设置、今天或明天的下一次计划时刻、暂停等停发原因、最近一次发送的日期与状态。
未勾订阅也可看状态；惯常时间不足五场无法算出时会说明，按提前量的提醒在静音时会提示被挡，
每天定时则不受静音影响。下一次按实际调度的到点计算和已有发送记录给出，今明两天不符合条件时也会直说。

点「试发开播前提醒」会立即向当前标为主播本人的好友通道发送同样的正文。
暂停、静音、全局推送关闭须逐项确认；本人说过不要或档案读不出时拒发。
没有可展示名字时说明没有要特别留意的，不发送空提醒。试发不记进发送记录，也不算当天那一条，当天定时的照常发。
这与本人私聊「准备开播」占用当天名额的行为不同。成员只能查看和试发分给自己的主播。
接口为 `GET /config/api/pre-live-reminder/{platform}/{uid}/status` 和
`POST /config/api/pre-live-reminder/{platform}/{uid}/trial`，通道参数与私聊小结相同；
试发确认参数为 `confirmPaused`、`confirmQuiet`、`confirmDisabled`，默认均为 false。

机器人未就绪时不发提醒，回「机器人刚启动，请过一会儿再说一次」；发送记录读不出时不发，回「发送记录暂时读不出，这次没发，请稍后再试」。

档案新增 `preLiveLeadMinutes`（未设置为 null）、`preLiveDailyTime`（未设置为 null）和
`preLiveDisabled`（默认 false）。旧档案没有这些键时按默认提醒读取，保留 READY，
不会进入坏件流程；每次写入带上这些键，其他档案命令会保留提醒设置。
