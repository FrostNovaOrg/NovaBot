### 6.2 豁免清单的阳性对照（端到端重演）

豁免清单是整套扫描里**唯一一个能让红消失的部件**。它坏掉的样子和「真的干净」一模一样，
所以必须先种一条已知的红、确认扫描器**报得出来**，再撤掉、确认回到 🔴 0。
**只看到 0 不算数**——没有前半段，那个 0 也可能是管道断了（共同纪律 34）。

种子是合成的：取固定字面量 `novabot break-run positive control 2026-08-20` 的 sha256
做 urlsafe base64，**不是任何真实凭据**，可当场复算。它同时过扫描器那三道闸：
`SECRET_STANDALONE` 命中、`looks_secret` 为真、香农熵 **4.711** ≥ 4.0。

> 🔴 **种子必须 `git add -f`。** `scan --all` 是照 `git ls-files` 枚举的，未跟踪的文件它根本不看——
> 上一轮我就是这么把「种下去了却报 0 命中」当成过了对照。那个 0 是「没在扫」，不是「没有红」。

| 读数 | 时刻 | 🔴 | 扫描器报的 |
|---|---|---:|---|
| 一（种红） | 2026-08-20 13:02:53 +0800 | **1** | `docs/break-run/__positive_control__.txt:4 [独立高熵串]`，末尾判「有 1 条需要处理，**不要推送**」 |
| 二（撤除） | 2026-08-20 13:03:12 +0800 | **0** | 「无红色命中，5 条黄色待你过目后再推」 |

两个读数是同一条命令 `novabot-scan.py scan --all`，中间只差种子在不在树上。

**读数一还顺带证了第二件事**：那一跑「已豁免」仍是 **13 条**，没有变成 14 ——
说明种下的红是**照常报出来**的，不是被豁免清单吞掉之后又从别处冒出来的。
（扫描器内部另有一条常驻对照钉同一件事：拿种子的内容指纹去查清单，查得到就报阳性对照失败。）

种子不留在树里，读数留。

### 6.3 落点先验的阳性对照

`breakrun.py --check-anchors` 是这一轮新加的：开跑第一步把所有变体的落点验一遍。
**只会说「都过了」的检查不算检查**，所以也给它种一次红：

| 读数 | 做了什么 | 结果 |
|---|---|---|
| 一（种红） | 把 `MINT_BURST` 临时改成 5 | 点名 **S 与 R** 两个变体命中 0 次，退出码 **1** |
| 二（撤除） | 还原被测文件 | **23 个变体的锚点全过**，退出码 0 |

这道闸是被真事逼出来的：整跑 21 个变体时，跑到**最后一个**变体 R 才发现它的锚点
写死 `MINT_BURST = 3`，而本批把标定改成了 4。硬停是对的，但那是在 45 分钟之后，
且当时 JSON 只在收尾写一次，**前面 20 个变体的读数一条没留下**。
现在：锚点开跑前一秒就验，读数每跑完一个变体落一次盘
（`跑完` 时刻只在收尾那次盖上，**没盖上的就是半份**）。

### 6.4 头一跑（733ff4e）证伪了变体 S 的预期

同目录 `733ff4e.json` 是**改判据之前**那一跑的原始记录，特意存档：
