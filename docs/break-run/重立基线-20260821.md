# 重立基线：已交付案卷的字节对照（2026-08-21）

`render.py` 里有一条对照项：**已交付的老案卷重渲染后必须逐字节相同**。
它是「改渲染脚本没改动历史读数」的哨兵。

本次改动（缺键拒出覆盖率格 ＋ 旧 JSON 补键）**会让其中一份的字节变化**，
所以按裁决 #182 ⑦ 显式重立一次基线，并把口径改写为：
**逐字节相同，除非有显式记录的重立基线。**

> 对照项的价值是「变了会被发现」，不是「永远不变」。
> 悄悄变才是坏的；**记录着变、并证明变的不是读数**，对照项仍然成立。

## 二、唯一那处变化的全文 diff

```diff
342c342
< - 这三个类里被红过的判据：**25** 条
---
> - 这 3 个类里被红过的判据：**25** 条
```

**全篇只有这一行不同，且不同的只是数字的写法**：中文数字「三」→ 阿拉伯数字「3」。
**读数（`**25**` 条）一个字没变。**

成因：老 JSON 缺 `本批类` 键时，渲染走的是写死的 `"三"`；补键之后走 `f" {len(...)} "`。
**这一格变化正是「不再用编出来的默认值」的直接结果。**

## 三、补的键是从哪儿来的（不是凭印象填的）

各案卷的键，取自**跑那一次时所用的那一版脚本**，用 `git show <rev>:docs/break-run/breakrun.py` 读出：

| 案卷 | 脚本版本 | 本批类 | 本批新增判据数 | 变体总数 | 本跑变体数 |
|---|---|---|---|---|---|
| `84e3358.json` | `f62f80a`（脚本与该案卷同一提交进树） | 3 | 23 | 18 | 18（整跑） |
| `733ff4e.json` | `733ff4e` | 5 | 26 | 21 | 3（挑跑） |

补键前有一道断言：**JSON 里 `变体` 的实际条数必须等于要补的 `本跑变体数`**，对不上就不补。

## 四、fail-closed 的阳性对照

拿 `d862a36.json` 做探针，逐个抽掉键：

| 抽掉 | 拒出覆盖率格 | 其余段落完好 | 没有偷偷用默认值 |
|---|---|---|---|
| `本批新增判据数` | ✅ | ✅ | ✅ |
| `本批类` | ✅ | ✅ | ✅ |
| （键齐，阴性对照） | 不喊缺键 ✅ | — | 照常给出覆盖率 ✅ |

🔴 **「其余段落完好」这一列是有来由的**：拒出这一格的第一版我写成了 `return`，
而它在 `main()` 里——那会**整份案卷都渲不出来**，等于把「这一格不可信」办成了「什么都没有」。
**fail-closed 要拒的是那一格，不是整件事。**
