# 第 2 章　开始之前要准备什么

装 NovaBot 之前要凑齐五样东西。这一章逐个说清楚，也讲讲怎么选 QQ 机器人、怎么准备官方机器人，以及为什么建议登录哔哩哔哩账号。

## 五样东西

| 要准备 | 说明 |
|---|---|
| 一台能长期开机的机器 | Linux、macOS、Windows 都行。**内存备到 1 GB 以上**，512 MB 不够用（为什么见[附录 A](appendix-a-measurements.md)） |
| JDK 17 | 只在这一个版本上验过。没有 Java 时，一键安装会自动装 17；机器上装着的 Java 比它新时，一键安装不停，会另找或另装一份 JDK 17、只给这一次构建用，机器默认的 Java 不动。手动跑 `./build.sh` 构建会停下，要先把 JDK 17 排在 PATH 最前 |
| Maven 3.9 或更高版本 | 从源码构建要用。要自己先装好，一键安装不替你装；没有就在构建前停下 |
| 一个 QQ 机器人 | 你可以用 NapCat，也可以用 QQ 官方机器人。按下面的说明选就行 |
| 一个哔哩哔哩账号 | **建议用小号**，原因见[为什么建议登录哔哩哔哩账号](#为什么建议登录哔哩哔哩账号) |

## NapCat 和 QQ 官方机器人怎么选

- **NapCat**：用一个普通 QQ 号扫码登录，群推送、好友私聊、QQ 告警都能用。先装好 NapCat 并登录 QQ，再到 NovaBot 接上。[NapCat 的安装和登录说明](https://github.com/NapNeko/NapCatQQ)
- **QQ 官方机器人**：用 AppID 和 AppSecret 连接，不用扫码，也就没有通过 NapCat 登录个人 QQ 号带来的封号风险。要让群收到主动推送，得请群主开主动发言。每群每天只能 @全体成员 一次，暂不支持私聊或好友推送。

## QQ 官方机器人要准备什么

- 到 QQ 开放平台创建机器人，拿到 AppID 和 AppSecret，等连接时填。个人主体的机器人只能加入你担任群主或管理员的群。[QQ 开放平台](https://q.qq.com/)
- 在 NovaBot 连接页的「QQ 官方机器人」卡里，「发送间隔（毫秒）」默认是 2000，可设 1000 到 60000。按默认间隔，所有官方群合起来，每分钟最多发送 30 条排队的推送。
- 做过认证可以把间隔调短。连接页的提示是「每分钟 60 条只对做过个人认证或企业认证的机器人有效，没认证的超频会被拒」。
- NovaBot 还限制同一个群在任意一分钟内最多发 20 条。达到上限后，后面的消息会排队，等先发的消息满一分钟、腾出额度再发。
- QQ 开放平台后台的 IP 白名单可以留空。如果要填，只填 NovaBot 所在机器的固定出口 IP。家里宽带的出口 IP 变了，白名单还留着旧地址时，机器人会连不上。
- 一只机器人请只给一套 NovaBot 用。你有几套 NovaBot 要分别连接，就给每套准备各自的机器人。

## 为什么建议登录哔哩哔哩账号

开播、下播本身是公开信息，不登录也判断得了；但**直播间里的弹幕、礼物这些数据，
不登录时平台只给一小部分**：

- 拿到的数据整体变薄——不是某一类缺，是按比例少
- 弹幕看不出是谁发的（用户编号被抹掉、昵称只剩第一个字）
- 动态推送、自动关注这类功能直接用不了

少到什么程度、什么样的房间会好一些，实测数字都收在
[附录 A](appendix-a-measurements.md)。结论只有一句：**要完整数据就登录，并且用小号**——
采集用的账号万一被平台风控，不至于连累大号。

> [!WARNING] 不登录能不能用：能。程序照常跑、日志干净、报告照常出，只是数字系统性偏低，
> 不拿两边比对就发现不了。确实不想登录的，[第 4 章](04-first-open.md)有「匿名模式」的打开方法。
