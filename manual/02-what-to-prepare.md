# 第 2 章　开始之前要准备什么

装 NovaBot 之前要凑齐四样东西。这一章逐个说清楚，顺带讲两个「为什么」：
为什么必须先有 NapCat，为什么建议登录哔哩哔哩账号。

## 四样东西

| 要准备 | 说明 |
|---|---|
| 一台能长期开机的机器 | Linux、macOS、Windows 都行。**内存备到 1 GB 以上**，512 MB 不够用（为什么见[附录 A](appendix-a-measurements.md)） |
| JDK 17 | 只在这一个版本上验过。装着的 Java 比它新时，安装和构建都会停下让你先处理；没有 Java 时，一键安装会自动装 17 |
| 一个 OneBot 实现 | 推荐 [NapCat](https://github.com/NapNeko/NapCatQQ)，由它负责真正登录 QQ、收发消息 |
| 一个哔哩哔哩账号 | **建议用小号**，原因见下一节 |

## 为什么必须先有 NapCat

NovaBot 自己不登录 QQ。它只决定「什么时候、往哪、发什么」，真正把消息发出去的是
OneBot 实现。所以顺序是：先把 NapCat 装好、登录上 QQ，再回来装 NovaBot——
反过来的话，NovaBot 装好了也无处发消息。

NapCat 怎么装、怎么登录，见[它的仓库说明](https://github.com/NapNeko/NapCatQQ)。

## 为什么建议登录哔哩哔哩账号

开播、下播本身是公开信息，不登录也判断得了；但**直播间里的弹幕、礼物这些数据，
不登录时平台只给一小部分**：

- 拿到的数据整体变薄——不是某一类缺，是按比例少
- 弹幕看不出是谁发的（用户编号被抹掉、昵称只剩第一个字）
- 动态推送、自动关注这类功能直接用不了

少到什么程度、什么样的房间会好一些，实测数字都收在
[附录 A](appendix-a-measurements.md)。结论只有一句：**要完整数据就登录，并且用小号**——
采集用的账号万一被平台风控，不至于连累大号。

> [!WARNING] 不登录能不能用：能。程序照常跑、日志干净、报告照常出，只是数字系统性偏低，
> 不拿两边比对就发现不了。确实不想登录的，[第 4 章](04-first-open.md)有「匿名模式」的打开方法。

东西齐了，下一章开始装：[第 3 章　安装](03-install.md)。
