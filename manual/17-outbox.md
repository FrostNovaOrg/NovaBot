# 第 17 章　外发箱

外发箱把直播通知保存在 NovaBot，供另一台设备取走。适合由值班人员转发，或由已有的发件程序接手。发行包里的取件程序会把每条通知整理成一个本机文件夹；发件人或发件程序挪动文件夹，取件程序就把结果告诉 NovaBot。外发会话的名称由你登记，实际发到哪里由发件的一方决定。

> [!WARNING] 把通知发到别的聊天软件时，请遵守那个软件自己的规则。用自动化手段操作别的软件可能违反它的规则，由使用者自行判断并承担责任。

## 在控制台准备外发会话

1. 用管理员账号打开控制台，点「外发箱」→「会话」→「新增会话」。填写一个易辨认的名称，例如「早班通知」，点「保存」。需要限制数量时，可同时填最小间隔和每日上限。
2. 打开「推送」，选要发送通知的主播，点「添加通道」。去向选刚登记的「外发」会话。名单按会话名查找，可用会话编号核对。打开需要的通知类型后点「保存」。
3. 打开「访问令牌」，取个容易辨认的名称，例如「早班取件」，**只勾**「读取外发箱」`outbox:read` 和「投递外发通知」`outbox:deliver`，选有效期，再点「签发令牌」和「复制」。令牌只显示一次，请妥善保管。取件账号须能看到要取件的主播。用下面「发送测试消息」验证时请用管理员签发的令牌，因为这类测试消息没有主播归属。

如果侧栏没有「外发箱」，请确认 NovaBot 已加载发行包自带的「外发」插件，并用管理员账号登记会话。关于签发和吊销，可查看[附录 B「让脚本或别的程序调用 NovaBot」](appendix-b-advanced.md#签发一把令牌)。

## 在取件设备上放好程序

1. 在取件设备装好 Python 3.8 或更新版本。从 NovaBot 发行包的 `tools/` 复制 `outbox-pickup.py` 到自己的文件夹，例如家目录下的 `NovaBotPickup`。
2. 准备连接方式，想好取件设备该用哪个地址（见下面「地址该填什么」）。如果使用隧道，启动取件程序期间要保持隧道连通。
3. 在命令行进入存放脚本的文件夹。macOS 或 Linux 运行 `python3 outbox-pickup.py`，Windows 运行 `py -3 outbox-pickup.py`。第一次会在脚本旁生成 `outbox-pickup.json`，提示填写后退出。
4. 用纯文本编辑器修改设置文件。保留双引号、逗号和大括号，保存为 UTF-8。`address` 填取件设备实际用来访问 NovaBot 的地址，若有部署前缀，一并填入。通过本机的隧道端口连接时可用样板地址。`token` 填刚复制的令牌。

```json
{
  "address": "http://127.0.0.1:7827",
  "token": "<访问令牌>",
  "work_folder": "取件",
  "interval_seconds": 60
}
```

### 地址该填什么

`address` 只填到端口（有部署前缀时连前缀），不带 `/nova/api/v1`。控制台「访问令牌」页最下面的
「从别的机器访问」（管理员看得到）按这台机器此刻的设置写好了每种连法与现在通不通，可以对照着填。

- **取件程序与 NovaBot 在同一台机器上**：`http://127.0.0.1:7827`，什么都不用改。前提是「监听地址」是默认的
  `127.0.0.1` 或 `0.0.0.0`；设成了某一个具体地址（例如 `192.168.1.20`）时要填 `http://192.168.1.20:7827`，
  而且这样连进来的不算本机，要由管理员打开「外发箱」。
- **取件设备在同一个内网**：`http://<NovaBot 那台机器的内网地址>:7827`。先在设置页把「监听地址」改成
  `0.0.0.0`（或那台机器的内网地址）并重启；再由管理员在「从别的机器访问」里打开「外发箱」。
- **取件设备在公网**：`https://<你的域名>`，经 NovaBot 那台机器上的反向代理连。反向代理要按
  [附录 C 的样板](appendix-c-security-and-resources.md#让别的机器经反向代理调程序接口)转发 `/nova/api/v1/`，
  管理员还要在「从别的机器访问」里打开「外发箱」。**控制台的公网地址不一定能调接口**：
  反向代理只转发了 `/config` 的，照着控制台地址填会连不通；转发了接口、开关没开的，会收到 HTTP 403。
- **用 SSH 隧道**：在取件设备上开 `ssh -N -L 7827:127.0.0.1:7827 用户名@服务器地址`，地址填 `http://127.0.0.1:7827`。
  不用改 NovaBot 的任何设置，取件期间保持隧道连通。监听地址设成了某一个具体地址时，命令里的 `127.0.0.1:7827`
  要换成那个地址（如 `7827:192.168.1.20:7827`），而且同上要打开「外发箱」。

各种连法的细节见[附录 B「从另一台机器连」](appendix-b-advanced.md#从另一台机器连)。

`work_folder` 是交接通知用的文件夹。相对路径从设置文件所在的文件夹算起，也可以填完整路径，Windows 可写成 `C:/NovaBotPickup/取件`。每套工作文件夹对应一个 NovaBot 实例；接到另一套实例时请另选工作文件夹。同一个工作文件夹只能启动一个取件程序。`interval_seconds` 是正常两轮之间等待的秒数，默认 **60 秒**。也可以把令牌放在 `NOVABOT_OUTBOX_TOKEN` 环境变量，取件程序会优先使用这个值。把工作文件夹留在本机磁盘上，避免其他人改动里面的取件记录。

用刚才的启动命令再运行一次，就会持续取件。想试一轮时在命令末尾加 `--once`，跑完便会退出；这一轮连不上或遇到其他暂时故障时，退出状态为 1。持续运行时遇到暂时故障会显示原因并延长等待，恢复后回到正常间隔。

> [!WARNING] 请妥善保管设置文件和访问令牌。取件程序会把设置文件设为只允许当前用户读取和修改。离开本机的连接请走加密连接；直接使用远端 HTTP 时，令牌会明文经过网络。

## 开机登录后自动运行

先按上面的步骤手动跑通，再设置自动运行。以下做法会在指定账号登录桌面后启动取件。桌面退出登录或设备关机时，取件会停下。

### macOS

假设脚本放在家目录的 `NovaBotPickup`。把下列两行存为同目录下的纯文本文件 `start-pickup.command`。先在命令行输入 `command -v python3` 查看 Python 3 的完整路径，将示例中的 `/usr/local/bin/python3` 换成显示的路径。

```sh
#!/bin/sh
exec /usr/local/bin/python3 "$HOME/NovaBotPickup/outbox-pickup.py"
```

在命令行执行 `chmod +x ~/NovaBotPickup/start-pickup.command`，先双击确认能启动，再关闭测试窗口。打开「系统设置」→「通用」→「登录项与扩展」，在「登录时打开」点 `+`，加入 `start-pickup.command`。下次登录会打开取件窗口，保留窗口即可持续取件。

### Windows

假设脚本放在用户目录的 `NovaBotPickup`。把下列两行存为纯文本文件 `start-pickup.cmd`，保存时确认末尾是 `.cmd`。先双击确认能启动，再关闭测试窗口。

```bat
@echo off
py -3 "%USERPROFILE%\NovaBotPickup\outbox-pickup.py"
```

按 `Win+R`，输入 `shell:startup` 并回车。把 `start-pickup.cmd` 放进打开的启动文件夹。下次用这个账号登录时会打开取件窗口，保留窗口即可持续取件。

## 试发一条并确认结果

1. 在控制台「连接」页找到「发送测试消息」，选择刚登记的会话后发送。列表可能给会话名加上「群」前缀，可用名称和编号核对。到「外发箱」→「记录」确认有新记录。也可以用该主播的真实通知验证通道设置。
2. 到取件设备的 `待发` 打开新出现的通知文件夹。确认 `会话.txt`、`正文.txt` 与 `说明.txt` 都在；有随通知保存在外发箱的图片时，也会看到对应的图片文件。控制台的记录此时为「发送中」。
3. 将**整个文件夹**移入 `已发`，表示测试消息已处理。等下一轮取件，文件夹会移到 `已回报` 下以当天日期命名的子文件夹。回到控制台「外发箱」→「记录」，确认状态变成「已发」。

日常使用时，先看 `说明.txt` 里的到期时间，再由负责发送的人或程序发出。发成、失败或决定跳过后，把整个文件夹移到 `已发`、`没发成` 或 `跳过`。需要说明理由时，先在通知文件夹里放一份 UTF-8 的 `原因.txt`，取件时只读第一行的前 200 字。请用移动，避免复制出两份，也请保留文件夹里的 `.outbox.json`，它用来将结果对回原记录。

| 文件 | 内容 |
| --- | --- |
| `会话.txt` | 原会话名称。文件夹名不能使用的字符会在文件夹名里换掉；名称含换行时用带引号的文字和转义符保留原值 |
| `正文.txt` | 按顺序拼接的文字，保留文字段里的换行 |
| `图片-1.png` 等 | 取回的原图，按出现顺序编号，扩展名按图片类型；未识别的类型使用 `.bin` |
| `说明.txt` | 主播、推送种类、UTC 到期时间、是否原本要 @ 全体，以及通知里指向图片的网址；程序只记录网址。指向本机、内网或主机名解析不出的网址入箱时就已去掉，不会出现在这里，见[第 12 章](12-settings.md#改完怎么保存) |
| `原因.txt` | 可选，发件方填写的结果说明 |
| `回报未被接受.txt` | 若该次结果无法提交，说明随文件夹留在 `已回报` |

## 状态、有效期与限量

| 控制台状态 | 含义 |
| --- | --- |
| 待发 | 通知已经入箱，等待取件 |
| 发送中 | 已被认领，等待回报 |
| 已发 | NovaBot 已收到「已发」结果 |
| 没发成 | NovaBot 已收到失败结果，例如发件失败、原图缺失 |
| 跳过 | NovaBot 已收到跳过结果，例如文件夹在 `待发` 留到过期 |
| 结果不明 | 已认领，超过等待时间仍未收到回报。该次认领的迟到回报仍可更新状态 |
| 过期未发 | 到期前无人认领 |
| 超限未入箱 | 触发会话的最小间隔或每日上限，通知没有进入待发 |
| 已作废 | 管理员作废了待发通知 |

默认有效期从通知入箱算起。开播 10 分钟、下播 30 分钟、动态和其他通知 60 分钟、直播报告和下播打赏播报 6 小时。到期后无法再认领。已经取到本机的通知，按 `说明.txt` 写的到期时间处理。在到期前发出去，并把整个文件夹移入 `已发` 即可。一直留在 `待发` 的通知到期后会回报「跳过」，说明为「过期未发」。

从认领起默认 **15 分钟**还没收到回报，控制台会先显示「结果不明」。即使通知仍在有效期内，也可能看到这个状态。该次认领的回报到了，状态就会更新为实际结果。管理员重新放回待发后，原来的回报会失效。有效期、认领超时和记录保留时间都可在 NovaBot 设置里调整。服务端默认从入箱起保留记录和图片 **14 天**，保留期结束后便无法再回报。

每个外发会话可单独设「最小间隔」和「每日上限」，`0` 表示不限。上限按 NovaBot 所在设备的日期计算。超限时控制台仍能看到原因，但取件设备收不到这条通知。会话停用后，新通知不能入箱，已有的待发通知仍可取走。

## 待发通知久未取走时告警

管理员可在「设置 → 推送」打开「待发通知久未取走时告警」，并设置「等多久算久未取走」。告警默认关闭，等待时长默认 5 分钟，可填 1 至 60 分钟。两项保存即生效。

NovaBot 大约每分钟检查一次。启用的外发会话中，只要有一条待发通知达到等待时长，就提醒一次。已经认领、超限未入箱的通知和已停用的会话不参与判断。通知过期后仍会显示取件异常，直到取件程序再次列待发或认领，而且已经没有等待过久的通知，才会报恢复。关闭开关会撤下异常提示，不发恢复告警。

告警收件人由[「设置 → 告警」](10-quiet-and-alerts.md#出问题时通知我)决定，告警不会发往外发会话。没配任何告警收件人时，首页健康自检和日志页时间线照样能看到异常。控制台「外发箱」页顶部会提示管理员，并显示本次启动以来最近一次取件是什么时候。

## 常见问题

- **文件夹一直不出现**。先确认控制台有对应记录，再看状态是不是「待发」。检查会话是否启用、通道是否保存、取件程序用的是不是预期的地址和工作文件夹。若提示缺少范围，重签令牌时勾齐 `outbox:read` 和 `outbox:deliver`，成员账号还须获准查看对应主播。原图缺失时会直接回报「没发成」。取图时断线或被限速，程序会重试。到期还没取到图才会回报「没发成」。
- **状态变成结果不明**。在取件设备检查程序是否运行、是否断网、通知文件夹是否已移进结果文件夹。回报到了就会更新状态。回报被拒时，去 `已回报` 查看 `回报未被接受.txt`。先核对消息有没有实际发出，再决定要不要由管理员在控制台重新放回待发，以免重发。
- **看到过期未发**。控制台的「过期未发」表示到期前没人认领；本机回报里的「过期未发」表示取到了，但过期前没有移出 `待发`，回报成功后控制台显示「跳过」。要补发时先确认消息是否仍有时效。
- **收到久未取走的告警怎么办**。检查取件设备是否开机、网络是否接通、取件程序是否还在运行。也可在「外发箱」页看最近一次取件，按告警里的会话名核对待发和过期通知。如果程序能连接但还有积压，检查它的运行日志、令牌权限和账号能否看到这些主播。
- **连上了却收到 HTTP 403**。说明里写着「这组接口没有对本机以外的地址开放」时，是取件程序不是从 NovaBot 那台机器上直接连的（别的设备、经反向代理、或连的是监听的那个具体地址）、外发箱也没对任何地址开放：请管理员在控制台「访问令牌」页的「从别的机器访问」里打开「外发箱」。「允许访问的来源 IP」只管控制台，把取件设备加进去没有用。
- **令牌失效或请求被限速**。看到 HTTP 401 时，到控制台检查令牌和账号状态。如令牌已过期或已吊销，重签一把、改好设置，再重启取件程序。看到 HTTP 429 时，程序会延长间隔，等它再试即可。
