# 手册怎么写（给写手看的说明）

本目录是用户手册的源文件。一条命令生成整站：

```bash
python3 manual/build.py
```

产物在 `manual/dist/`（已 gitignore，不入仓）。生成时会检查**全部站内链接、页内锚点和图片引用**，
有断链就报出「哪一页、哪个链接」并以退码 1 结束——本地写完先跑一遍再交。

## 章节怎么组织

- 每章一个 `.md` 文件，文件名只用 ASCII（如 `03-install.md`），**顺序不在文件名里，
  在 `chapters.txt`**：一行一个文件名，`#` 开头是注释。
- 清单和目录两对着账：列了但文件不存在、文件在但清单没列，生成都会红。
- 每章**恰好一个一级标题**（`# `），它就是目录、页标题和浏览器标签上显示的名字。
  章名建议写成「第 3 章　安装」「附录 A　实测数据与原理」（中间是全角空格）。
- 正在写的章可以先只放标题加一句「本章编写中」，目录里照样出现、链接照样通。

## 支持的 Markdown 写法

手册正文**只用**下面这些写法，生成器也只认这些：

| 写法 | 例 |
|---|---|
| 标题 | `# 章名`、`## 小节`、`### 小小节`（更深的不进页内目录） |
| 段落 | 一行一段，段与段之间空一行 |
| 无序列表 | `- 项目`（一层，不嵌套） |
| 有序列表 | `1. 项目` |
| 代码块 | 三个反引号围起来，第一行可写语言名（只作标记，不高亮） |
| 行内代码 | `` `代码` `` |
| 粗体 | `**重点**` |
| 链接 | `[文字](03-install.md)`（站内指向 `.md` 源文件，生成时自动换成 `.html`） |
| 页内锚点 | `[回到本节](#小节标题原文)`——锚点就是标题文字本身 |
| 表格 | 首行表头、次行 `---` 分隔、往后每行一条（单元格内不要写竖线） |
| 提示框 | `> [!NOTE] 说明文字`；三种：`NOTE`（说明）、`TIP`（提示）、`WARNING`（注意） |
| 引用 | `> 普通引用`（少用，多数情况用提示框） |
| 图片 | `![说明](images/文件名.png)`——图片放 `manual/images/`，生成时整目录带走 |

列表一项写不下可以折行，续行缩进两格。
粗体里可以再套行内代码与链接；图片不要写在粗体里。

不支持：嵌套列表、斜体、脚注、HTML 标签、自动链接、任务列表。
别用这些写法——它们会被当普通文字渲染出来。

**指站外的链接**（如 NapCat 的仓库）直接写完整网址，照常可用；
但不引任何站外的脚本、样式、字体。

## 截图占位的写法

本阶段手册不放真图，要截图的位置用提示框占位，写清三件事：要什么图、
重点看什么、哪些要打码。例：

```markdown
> [!TIP] 截图位（待补）：初始设置第 2 步「连上 QQ 机器人」整页。
> 重点露出「测试连接」按钮与回显的实现版本。地址栏里的 token 一整段要打码。
```

## 文风

- 读者是第一次用 NovaBot 的人：白话，按「我要做什么」组织，一步一句。
- 实验数据、类名、配置键不进正文，放附录 A；正文只留结论和「怎么办」。
- 跟着现码写：界面上没有的按钮不写，过时的说法不抄。
